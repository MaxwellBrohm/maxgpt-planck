SPEC CONFLICTS (Max or the next step decides)
  1. Turn counts: 2-4 events of 1-7 user turns each, plus opening and goodbye, do not fit the SPEC turn weights.
     The sampler draws T >= need, so 36% of chats have 12 user turns (SPEC 5%). Options: fewer events per chat,
     compound turns (two events in one user turn), or accept longer chats (token mean is still in range).
  2. S9 share: a 20% lookup slice with 1-2 S9 each gives 8% of events, not 5%. Implemented: slice 20%, S9 1 (80%)
     or 2 (20%), other kinds keep their relative SPEC shares.
  3. When a draw needs more than 12 user turns, shrink() reduces k, digression length, distractor, list ops,
     override, the goodbye closing, then drops the opening; kinds and variants are never changed. About 1% of
     seeds still redraw kinds.

DECISIONS NOT IN THE SPEC
  Held-out: pools and key nouns also ban held-out HEAD nouns (concert, reading, order...), stricter than the
    text gate. Marker stems banned whole: "oops", "on second thought", "hold on", "one more change/thing";
    "correction:" only with the colon. Hobbies exclude sport-like activities so H6's sport TYPE stays unseen.
    No "number" slot type; number words appear only as S2 counts, the max-words rule and times of day.
    Singleton key labels ("favourite food") count as object terms in frame-echo normalization.
    Lookup values count toward the 2-slots-per-type cap.
  Identity: S6 user_vs_card and S8 who_are_you force a system text that names the assistant. Without a system
    text, may_say drops "name" and every guided assistant turn excludes the card name.
  S6 variants 40/30/30 (two_persons, user_vs_card, role_swap); role_swap asks "what's your X?" and the gold is a
    denial with no self-claim. S7 abstain reserves its key or noun so nothing plants it later; candidates are
    all same-type values. S9: counterfactual = user states a belief, tool returns another value (gold = tool
    value, stale = belief); context = the user passed the fact on earlier; need split 70/30, result 70/20/10.
  Second S2 in a chat gets a different item type; lists are named (shopping list, route, guest list, chore list).
  Closing weights 40/35/25, topic path 1/2/3 at 40/40/20, system text 40% unless forced.

SCHEMA EXTENSIONS (SPEC section 2 shape kept)
  user.name may be null (the name is never said). Slots add key, noun, counted (counted = a planted fact for the
  2-per-type cap; list items, nickname, lookup values, card name are uncounted but still slots for R2).
  events[].params.ops is the replay list golds.derive uses. Turns add role_in_event, lookup_call, rules.
  Filler intents are ids "topic:<topic id>:<form>" (form indexes fake_data.INTENT_FORMS); S5 digressions use
  "topic:<id>:digress". attempt = [kind draw, layout attempt]; estimate = token estimate; topic_text.

DECISIONS
  Matching uses golds.value_re; capitalized values are case-sensitive except in turns of a lowercase-style user.
  ANSWER_SHOTGUN candidates: gold candidates + stale + every same-type value, minus what the turn must include.
  QUERY_RESTATES exempts only S2 contains queries ("yes or no" is not a leak); a count word in a count query is.
  PROMPT_ECHO covers the instruction head and tail, the card block and the script guidance (all Claude wording),
  with slot values, required spans, topics, persona and bank lines masked out. Rule guidance is telegraphic
  ("request a rule: one sentence per reply") because natural wording ("in one sentence from now on") collides with
  what a user would really say.
  With no system text the prompt never shows the card name; must_exclude still enforces it.
  Codes added to the SPEC list: STAGE_DIR, PLANT_UNBOUND, CORR_MISSING, VALUE_EARLY, USER_VOICE, ASSIST_VOICE,
  OPEN_END, SOCIAL_TOPIC, SKEL_INFEASIBLE (meanings in the checker.py docstring).
  Not checked yet: answer position (value first vs after a lead-in); VOCAB_OOL is wired and report-only until the
  real word list exists; the naturalness read; NGRAM/SENT/OPENING caps are shard level (diversity.py, later).

FINDINGS FOR THE SKELETON STEP
  1. d is skewed short: of S1 events, d=1 24%, d=9 2%, d=10 0.02%. SPEC 7 wants long d oversampled.
  2. 0.5% of skeletons cannot be rendered: a terse guided turn whose must_include alone is over 10 words (lists of
     multi-word items), a value that is also a topic word (rice, coffee, gardening), a value inside another noun
     (hobby "pottery" with a "pottery class"). feasible() catches them; the generator should not make them.
  3. A guided plant turn lists only the value in must_include. The checker now requires the noun (PLANT_UNBOUND);
     the skeleton should add it to must_include so the prompt shows it.
  4. After a bare greeting opening ("Hi!") the assistant intent is "greet back and engage with the topic", so it
     must raise a topic the user never mentioned (OFFTOPIC enforces it). Use a neutral reply there, or put the
     topic in the first user turn.
  5. Required-word hints land on turns with an 8-word cap and on role-swap denials.

YIELD RISKS TO MEASURE IN THE PILOT (strict by design, may cost accepted chats)
  ECHO_USER at 60% rejects acknowledgements that repeat a plant line almost word for word. SELF_CLAIM counts
  "I love" and "I like" as preferences (SPEC list), so "I love that idea" is rejected. OFFTOPIC needs one shared
  content word (crude suffix stemming). VALUE_EARLY rejects any mention of a scheduled value before its turn,
  including common words (a colour, "rice").

BEHAVIOUR
  Attempt 0, then one retry with a new seed (render_seed(skel_id, attempt)) after any reject except
  SKEL_INFEASIBLE (render_prompt.feasible runs before any request, so it costs nothing). Driver codes beyond
  checker.ORDER: TEACHER_ERROR (request failed after the client's retries; 408/429/5xx/timeouts/drops are retried
  with backoff, other 4xx are not), CHECKER_ERROR (the checker raised; the traceback text is in the record, the run
  goes on), DUP_EXACT, DUP_NEAR. A truncated render (finish "length") is rejected by the checker (FORMAT_LINES);
  the finish reason is in the record.
  Dedup: exact = sha256 of the normalized chat; near = MinHash (128 perms, 32x4 LSH) over word 5-grams with slot
  values masked by type, estimated Jaccard >= 0.7. A copy that differs only in slot values is DUP_NEAR (R2 makes
  those for free). On 598 fake renders: no false hits, max true Jaccard between different chats 0.19.
  Records: accepted records carry turns with author (bank:<ref>, teacher:<model>, program) and slot spans, slots,
  events + golds, gold notes, provenance (skeleton + teacher model, license, prompt variant, prompt sha256, seed),
  codes incl. report-only, drift, gate hash, rc12, est tokens (words x 1.3, flagged), trainable=false and
  blocked=[FAKE_PROVENANCE | LICENSE, DECON_PENDING]. Rejects carry primary, all codes, first failing line, hits,
  finish, usage and the raw teacher text (for measuring checker false rejects in the pilot).
  Yield: yield.jsonl snapshots every --log-every s and at the end: accepted/attempted, by primary, by every code,
  by cell (kind|variant|d bin, one count per event), accepted est tokens per hour (this session), completion
  tokens per second, mean latency.

SAFETY
  Without --allow-real-teacher the client refuses a non-loopback host before opening a socket, and on loopback it
  refuses unless GET /planck-stub answers as the fake stub. The driver checks this before writing anything. The
  stub sets license FAKE, so its records are blocked twice over. With --allow-real-teacher the license comes from
  the model id (gemma-4, ministral-3 -> Apache-2.0, anything else UNKNOWN -> blocked LICENSE) or --license.
