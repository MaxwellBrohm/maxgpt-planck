WHY
  Max (2026-09-27): how do we get a model to learn the skill part and not the facts; can we find which parameters
  hold facts and which hold skills, and overwrite the fact ones with ones that strengthen the skills? Planck's bet
  (REPORT 1.3 and 5.1 limit 7; LEDGER baseline row "scope the target to conversational mechanics over context plus
  lookup") is that 5M-150M parameters should go to skill while knowledge stays outside. K tests the pieces in a
  world where every fact and every skill item is known: K1 does a memorized fact load crowd out in-context skill
  (P-114; research/followup/bits.md 6.5 item 7); K2 where facts and skills sit; K3 prune fact units and regrow on
  skill data; K4 MLP-to-attention allocation (P-152); K5 a lookup channel vs memorization (P-082..P-094, P-142).
  Literature read for K (fact-checked 2026-09-27): experiments/K/research/capacity.md, localize.md, arch.md.

1 TOKENIZER AND POOLS (tok_v0_8k, sha256 078b24c4...cfb5 as E2 FIXED 3; the generator writes token ids directly)
  Frame tokens (single ids, checked 2026-09-27): " ?" 2479, " =" 847, " ok" 2708, " none" 5151. Control and tag
  tokens: <|endoftext|> 1, <|system|> 2, <|user|> 3, <|assistant|> 4, <|end|> 5, <|tool|> 6, <lookup> 11,
  </lookup> 12, <result> 13, </result> 14. No other fixed text exists in K data.
  Pools are drawn by rule, never by hand. CAP = the 778 vocab entries that are the byte-level space U+0120 then
  [A-Z][a-z]{2,}; LOW = the 3,913 that are U+0120 then [a-z]{3,}. Drop the 64 lowest-id CAP and the 256
  lowest-id LOW entries (the earliest merges, mostly function words), drop the frame tokens, keep only entries
  whose standalone encoding is that single id, then assign by a seeded permutation (world seed W = 7), in order:
    CAP (714 left): FB name pools F1, F2, F3 (112 each); filler pools Z1-Z3 (40 each); skill-train pools S1-S3
      (48 each); skill-eval pools T1-T3 (24 each); alias pool AL (32). About 10 spare.
    LOW (about 3,650 left): attribute tokens A (6, shared by facts and skill items); held-out attributes AH (6, OOD
      only); value pool V (2,048); held-out values VH (256, OOD only); marker pool MK (32, family P). Rest unused.
  A name is 3 tokens, one from each pool of a triple: FB 112^3 = 1.40M names, filler 64K, skill-train 110.6K (a
  seeded 10% never trained: K-EVAL-S names [C6]; [K3r2] whole cube cells: each of S1-S3 paired off by a seeded
  permutation into 24 token pairs, a cell one pair per position, 8 triples; 1,382 of the 13,824 cells, 11,056
  triples, so a K-EVAL-S B item is a held-out cube), skill-eval 13.8K. No token sits in two pools.
  If the drop rules leave fewer tokens than stated, pools shrink pro rata and the FIXED log records the sizes.

2 THE FACT BASE (world W; one world for every run, arm and seed)
  FB_high: N_high = 62,000 entities with distinct names from F1 x F2 x F3 and one value per attribute of A, uniform
  from V (11 bits): 66 value bits per entity. Name bits [C1]: only an item's first token is unsupervised, so bio docs
  train M given F and L given F M, and the FB triple set is learnable: log2(1.40M / N) bits per entity, 4.5 at N_high
  (0.28 Mbit, 6.8% of value bits), 6.5 at N_low, 3.5 at N_cap. FB_low = the first N_low = 15,500 of FB_high (nested:
  one probe set serves every arm). QA-train = a fixed seeded half of FB_high (and of FB_low); QA-held = the rest.
  Bio doc (plain token source; every token but the first supervised):
    F M L a1 v1 a2 v2 a3 v3 a4 v4 a5 v5 a6 v6 <|endoftext|>   16 tokens; the six pairs in a fresh random order at
    every exposure (the diversity Physics 3.1 needs for extraction, https://arxiv.org/abs/2309.14316).
  Fact QA (chat record, assistant loss): <|user|> F M L a ? <|end|> <|assistant|> v <|end|>, 10 tokens, the same
    question frame as the skill items (section 4): only where the answer lives differs.
  Exposure: every FB entity gets exactly E = 100 bio docs; every QA-train entity gets E_qa = 10 QA per attribute;
  QA-held entities get none (Physics 3.1 mixed training: bios for all, QA for half). 1,900 tokens per entity on
  average. Exposures sit at seeded uniform positions over the drawn FACT stream (section 7).

3 FILLER (the zero-memorization control; capacity.md: Physics 3.3 Result 11, token-matched low-information data)
  Filler docs use the FB formats exactly (bio docs and fact QA in the FB exposure ratio) with names from Z1 x Z2 x Z3
  and every value drawn fresh per doc, so no name-value pair can be learned, while format and token count match.
  Every arm's FACT stream has the same length and the same document-length sequence; arms differ only in which
  slots hold FB exposures and which hold filler. The FH slot plan is built first; FL is the FH plan with every slot
  of an entity outside FB_low turned into filler; F0 turns every slot into filler (K1 notes).

9 METRICS (scorer code/k_eval.py, fp32, one causal pass per item; every candidate is one token)
  Skill, per scored question: C = {gold} + every V value anywhere in the item, of any attribute [C4] + 3 V values
  not in the item + " none" (P items: scored after the gold marker y).
    LIK   argmax over C of log p(c | prompt) equals gold. Chance = mean 1 / |C|, reported per family.
    CE_C  -log softmax over C of the gold, nats (continuous companion; chance log |C|).
    GEN   greedy argmax over the whole vocabulary equals gold AND the next greedy token is <|end|> (strict). P: first
          answer token = y (persistence), reported by distance from the system turn.
    S_ID  LIK pooled over K-EVAL-ID (n 3,072; binomial SE 0.72 points at p 0.8): the primary skill number. Reported
          beside it: per family, matched vs crossed frames, every OOD column, earlier questions,
          F per reference kind of the key (exact halves, 256 each) [R-1], A split by whether one name states the
          asked attribute among 3 or more (A1H's context) [K3r2], B split cube (8 names) vs 2-4 names [K3r2] and B
          group accuracy on the cube groups (96 on K-EVAL-ID, 48 on K-EVAL-S) [K3r3], and
          wrong-pick classes (stale value of the key, another entity's value, another attribute's value, none,
          other). S_ID-S: the same on K-EVAL-S
          (n 1,536), reported beside S_ID in every table [C6]. Each family's LIK is printed beside its fitted
          cue-model ceiling on the same file (check.json cue_gate): a LIK at or under it shows no skill [K3].
  Facts: BIO_acc and QA_acc (greedy over the vocabulary equals the FB value), QA split train / held (extraction,
    Physics 3.1). Stored bits (Physics 3.3 Def. 4.3, value term): S = N x 66 - sum over entities and attributes of
    CE(v) / ln 2, CE in nats on the BIO prompt, mean of the 2 orders, estimated on the probe sample and scaled to N.
    "Expressed" uses full-vocabulary CE; "latent" renormalizes over V (both reported; K1-K4 read expressed, K5
    latent). Bits/param = S / P. F0's score on the same probe is the floor and is subtracted in every contrast.
    Name term [C1], reported beside S and added in K0-cap's R_cap: N x (log2 112^2 - CE of M, L given F in bits).
  Conflict: context-follow rate (gold), memory rate (the FB value), other; split by whether the arm's own BIO recall
    of that key is right (known) or not (arch.md F10: expect context-following at ceiling; stratify).
  Language: F(CHAT), F(PROSE) by data_prep/bpb.py at E2's fixed invocation (E2 METRIC), final checkpoint.
  Time course: K-PROBE LIK and BIO_acc every 153 steps; peak (max of the 5-checkpoint moving mean) and final (mean
    of the last 5) [C7] (Singh et al., https://arxiv.org/abs/2311.08360: in-context skill can rise, then fade).

10 DECISION RULE KR (SCREENS C7's shape on K metrics; each notes.txt names its contrasts, pool and delta)
  d_s = metric(arm, s) - metric(ref, s) at paired seed s; dbar over k seeds; SD_ref = pooled SD of the residuals
  d_s - dbar over the experiment's listed contrasts (df = sum of k - 1); thr = t(0.975, df) x SD_ref / sqrt(k)
  (t = 2.776 at df 4, 2.447 at df 6, 2.306 at df 8; scipy 2026-09-27).
    HIGHER  dbar > thr, every d_s > 0 and dbar >= delta          LOWER  the mirror image
    EQUAL   |dbar| + thr < delta                                  else UNRESOLVED ("not resolved", never "no effect")
  delta: S_ID 3 points (4.2 binomial SEs); GEN claims only at 5 points (PLAN Phase 3); stored bits 10% of the
  reference mean (the size of known architecture effects on capacity: Canon +10-15%, gated MLP 1.3x, capacity.md);
  CONFLICT and K5 rates 10 points. A skill HIGHER or LOWER also needs CE_C to move the same way (else UNRESOLVED,
  labelled CE-DISAGREE). DIVERGENCE as SCREENS C7 (a diverged arm seed scores +inf and is never dropped).
  E3's noise enters through bpb: WORSE_bpb as SCREENS C7 with E3's SD_d (u x SD_d for same-shape arms, sqrt(2) x
  sigma_init for K4's new shapes; E3 results.json sha256 in FIXED). It labels a verdict GENERAL-LANGUAGE COST and
  never decides one. Parameters read from E2/E3 are recorded in each experiment's FIXED log, as SCREENS C1.
  Multiplicity: raw verdicts decide; a Holm reading over every K contrast that ran is printed beside each one.
