QUESTION (decided, B7)
  Do role segment embeddings change held-out chat bpb (oasst2, scored per window as bpb.py does) at 5M, 250M slots?
  Prose bpb is the guard: prose tokens carry segment "none" and should not move.

THE CHANGE (one flag)
  model.role_segments: [2, 3, 4, 6] (new; default [] = off): the [system, user, assistant, tool] token ids, written
  into the config by the batch 2 generator from tokenizer/spec.py's control tokens and checked against it there,
  so the model holds no hard-coded id (fixed 2026-10-11 while writing the code, before any value).
  A table S (5 x 192): none, system, user, assistant, tool. Row 0
  ("none") is a fixed zero buffer, never trained (critique R6: a trainable none row would be a learned bias on every
  prose token, about 97% of the stream, a second change); rows 1-4 are the learned Parameter. The input
  is tok_emb(idx) + S[seg], seg computed inside the model from idx alone: seg_t = the role of the latest role token
  (ids 2, 3, 4, 6) at or before t within t's document, "none" if there is none; <|end|> (id 5) keeps its turn's role, so
  a turn's role token, content and end share one segment. Documents are doc's runs (packed rows); on the doc=None path
  (bpb.py, the IND hook) the row is one document. The token ids come from the tokenizer's control-token ids, read
  from tokenizer.spec at build and pinned in a test (never hard-coded in the model). The head is unchanged (tied to
  tok_emb only). Init: zeros (constant, no RNG draw): the arm starts as the exact BASE function and keeps every BASE
  draw. Parameters 4 x 192 = 768; total 5,010,901 (+0.02%). Optimizer: "embed" group (AdamW at embed_lr), routed by
  name (a 2-D table, like tok_emb).

WHAT STAYS IDENTICAL  B1 (engine varlen: the segment ids are a function of idx and doc, computed before the blocks).
  The data, the loader and bpb.py are unchanged: no segment ids are passed from outside (a test).

KNOWN RISKS
  - Chat-kind tokens are 2.8% of the starter stream (dolly, oasst2), so the table trains on few tokens at 5M; the 30M
    test on a pool mix is where the bet is judged.
  - Windows that start mid-turn (the loader cuts items longer than max_item_len; bpb windows can enter a turn mid-way)
    give "none" until the next role token, in training and in scoring alike.
  - The segment repeats information the role token already carries; a gain, if any, is in how cheaply it is used.
  - Starter mix and tok_v0_8k only.
