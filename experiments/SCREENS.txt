  PLAN Phase 3: "Each bet is one change against the baseline, pre-registered, with paired seeds (common random
  numbers). Decisions rest on continuous metrics: fixed-window bits per byte, plus the Tier 0 log-prob margin.
  Generative pass rates count only for effects of 5 points or more."
  Constraints on this batch:
  - RC-12 is not locked, and no Planck model is scored on any RC-12 split, dev included, before the lock (PLAN
    Phase 0, hard rule). So the Tier 0 margin is not available: these screens DECIDE on bpb (E2/E3's CHAT and
    PROSE) and REPORT non-RC-12 diagnostics (C6). Tier 0 is added after the lock (C8).

    baseline loss dropping 6-16 downstream points (research/lanes/arch.md 1.4, citing arXiv 2605.20798). So a bpb
    WIN here only NOMINATES a bet for the post-lock Tier 0 reading and a 20-30M confirmation (PLAN 3: adopted only
    if it passed at 5M AND held at 20-30M AND survived 3f).

C4 SEEDS, PAIRING, REFERENCE NOISE
  Seeds 101, 102, ..., 100 + k (fresh: E2 used 1, E3 1-11). k = max(2, k_needed(1%)) for the arm's class, at most
  5; if k_needed exceeds 5 the arm runs 5 seeds and is labelled "underpowered", and a null reads "not resolved"
  (E3 rule 2). At seed s every arm reads the identical token stream: the loader draws from its own numpy
  generators seeded by the run seed (harness/data.py, default_rng([seed, w, 11]); harness/sources.py,
  default_rng([seed, epoch, 7])), not from the torch RNG, so an arm that draws a different number of init values
  still gets BASE's stream. Every parameter created in the same order starts from identical draws.
  Class (model.py reset_parameters draws only nn.Linear and nn.Embedding weights; RMSNorm gains and value-residual
  scalars are constants):
    same init   E3 rule 1's first row (LR, optimizer, schedule, weight decay, clip, loss masks): S003 only.
                SD_ref = SD_d, df_ref its df; per-arm noise check below.
    SIA         same-init architecture. E3 rule 1 puts "architecture or shape" in the NEW INIT row, and its
                KNOWN LIMITS say "bets that move the model more may be noisier" than the LR-only contrast that
                measured SD_d. E3 allows a looser rule only if the pre-registration says why, so this is recorded
                as a LOOSENING: these arms keep every BASE draw bitwise (tested, below), so the init-noise term that
                the new-init row adds is absent. The looser SD_d is not used bare: SD_ref = u x SD_d, u =
                sqrt(df / chi2(0.20, df)), E3's 80% upper bound for SD_d (E3 KNOWN LIMITS "about a factor of
                1.35"; scipy, 2026-09-26: u = 1.353 at df 7, 1.398 at df 6), df_ref = SD_d's df.
                Members: S002's three arms, and S004, S005, S006, S007 when their init-isolation test passes in
                the committed harness (each registers a constant init that draws nothing from the torch RNG).
                S006 changes the objective, nearest E3's "loss masks" row, but it adds a trained module, so it is
                put here, the stricter reading.
    new init    removing or adding a drawn module shifts later draws (S001; any SIA candidate whose isolation test
                fails): SD_ref = sqrt(2) * sigma_init (sqrt(2) * sigma_seed if E3 Part 3 did not run).
  Noise checks. same init (S003): if the arm's own SD of d_s exceeds SD_d by more than sqrt(chi2(0.95, k-1) /
  (k-1)) (1.731 at k = 3, E3's refresh bound), it is re-read with the new-init SD. SIA: a per-arm check has df 1
  at k = 2, so the check is POOLED: before any SIA verdict is read, the residuals d_s - dbar of every SIA arm
  finished so far are pooled (df = sum of (k - 1) over those arms); if the pooled SD exceeds u x SD_d by more than
  sqrt(chi2(0.95, df) / df) (1.449 at df 6, 1.324 at df 12; scipy), every SIA arm is re-read with the new-init SD,
  including verdicts read earlier (re-labelled "noise check failed later"). An arm re-read with a larger SD than
  its k was chosen for is also labelled "underpowered" (a null reads "not resolved").
  One BASE run per seed serves every default-engine screen. S005 has its own BASE in the mask engine at S005's
  micro setting (registered micro 8 x accum 2, fallback 4 x 4, S005 notes), and S006 too if its memory needs micro

  is a flag defaulting off and the flag-off equivalence test passes at the later commit; otherwise BASE reruns
  (0.31 h).

C7 DECISION RULE (E3 "HOW LATER SCREENS USE IT" rule 3, both directions, per metric m in {CHAT, PROSE})
  d_s = F_arm,s - F_BASE,s (bpb; negative = arm better); dbar = mean over the k seeds; SD_ref from C4 (E3 carries
  it as a fraction of A's mean, so times BASE's mean F_m); thr_m = t(0.975, df_ref) * SD_ref / sqrt(k);
  delta_m = 1% of BASE's mean F_m (E3's default delta_bet).
  In E3's MDE units: MDE_p(k) = (t(0.975, df) + t(0.80, df)) * SD_ref / sqrt(k), so thr_m = c * MDE_p(k) with
  c = t(0.975, df) / (t(0.975, df) + t(0.80, df)): 0.725 at df 7 and 0.747 at df 4 (scipy, 2026-09-26).
    BETTER_m  -dbar > thr_m and every d_s < 0          WORSE_m  dbar > thr_m and every d_s > 0
    EQUAL_m   |dbar| + thr_m < delta_m (95% interval inside +-1%)          else UNRESOLVED_m
  Arm verdict: NOMINATE = BETTER_CHAT and not WORSE_PROSE. REJECT = WORSE_CHAT. TIE = EQUAL_CHAT and not
  WORSE_PROSE. GUARD-FAIL = BETTER_CHAT or EQUAL_CHAT with WORSE_PROSE. Else INCONCLUSIVE. Each notes.txt says what
  each verdict means for its bet.
  DIVERGENCE (E2 RULES: a divergence "scores +inf on every metric"): an arm run that goes non-finite at a screen
  seed gives d_s = +inf on every metric for that seed; it is never dropped (dropping it would bias the verdict
  toward the unstable arm). So dbar = +inf: the arm can never be BETTER or EQUAL, never NOMINATE, TIE or
  GUARD-FAIL; it is labelled UNSTABLE, and reads REJECT if every other d_s > 0, else INCONCLUSIVE. A diverged BASE
  run drops that seed from every contrast that uses it (C9); fewer than 2 remaining seeds reads INCONCLUSIVE.
  MULTIPLICITY: nine contrasts remain (S001 1, S002 3, S003 1, S004 1, S005 1, S006 1, S007 1), plus C8's second
  chance (NOMINATE-MARGIN) after the lock. The raw verdicts above decide; the 20-30M confirmation is the error
  control (PLAN 3 adoption rule). The analyzer also reports, beside each raw verdict, a Holm reading: the two-
  sided p of dbar_CHAT / (SD_ref / sqrt(k)) on t(df_ref), Holm step-down at family 0.05 over every contrast of the
  batch that ran (after the lock the family also holds each contrast's Tier 0 margin test), labelled "holds" or
  "does not hold". A NOMINATE that does not hold under Holm says so in the ledger row.
  TIE reach: when MDE_p(k) is just under 1% (k = k_needed) and thr_m = c x MDE_p, EQUAL needs |dbar| < about
  0.275% at df 7, about 0.9 standard errors: a true null then reads TIE only about 63% of the time (normal
  approximation, scipy, 2026-09-26). An INCONCLUSIVE null is therefore expected often and reads "not resolved",
  never "no effect".
