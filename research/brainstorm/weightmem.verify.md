# Fact-check: weightmem.md (memory baked into the weights)

Checked 2026-09-23 against primary sources. Every paper below was downloaded from arXiv, ACL Anthology or NeurIPS proceedings and read as text with pdftotext; numbers marked "table read" were read from the paper's own table, not a summary. Nothing was trained, loaded or run. Verdicts: confirmed (the source agrees), corrected (the gist holds but a number, scale, attribution, mechanism or generalization is off), refuted, unverifiable. Sizes are the model the number was measured on.

## Verdict in one paragraph

The report's numbers are mostly right; 5 of the 7 load-bearing claims survive, 2 with corrections that matter. The headline answer ("nobody has done this below 150M") only survives in its narrowest form. Per-persona weight adaptation of tiny chat models from a user's own past dialogues is 2019-2020 work (PAML, CMAML), and per-user LoRA consolidation with sibling-user contamination and conflict events was run on GPT-2 in June 2026 (EVAF). Weight editors were also measured inside a 90M chat model (SERAC's BlenderBot-90M table), where MEND and ENN failed. Four ledger ideas marked "untested" have direct or near-direct precedents. The most important is the rebuild-vs-stack comparison (L2): it exists at T5-small 60M in GRACE's own table, which the report cites without recognizing that its "fine-tune with retraining" row is the rebuild arm. Two mechanism descriptions are wrong: MAC does not fine-tune (it is a tiny context-to-modulation hypernetwork at 82M), and GradMem ran only on GPT-2 124M (Pythia-160M and Mamba-130M are baselines).

## The tiny-scale answer, restated

What exists at 150M or below, closest first:

1. **PAML (2019) and CMAML (2020):** from-scratch Persona-Chat models far under 150M; per-persona weights written by a few gradient steps from that persona's other dialogues, tested on a held-out dialogue. Measured: NLI consistency with the persona sentences, human consistency, perplexity, BLEU. Not measured: recall of facts a user told the assistant, bleed, corrections. Also the only tiny-scale evidence that plain fine-tuning on the transcript does nothing (C 0.00) while a meta-learned write does (C 0.20).
2. **EVAF (June 2026):** per-user LoRA consolidation on GPT-2 with factual notes, conflicts, context unload and sibling-user contamination measured. Base LM, forced-choice scoring, and weight memory lost to retrieval on facts (naive LoRA 0.733, EVAF 0.463, RAG 0.956).
3. **Persistent memory adapters (March 2026):** frozen GPT-2 124M, a Hebbian outer-product state (a fast-weight memory) carried across LoCoMo sessions, F1 gains of about 7-18 points. No bleed test, no in-context bound.
4. **SERAC ConvSent (2022):** weight editors (MEND, ENN) inside BlenderBot-90M fail (ES about 0.5, KL drawdown 2.1-3.5); the external memory works.
5. MAC (82M, a hypernetwork that writes document memory), GradMem (GPT-2 124M only), MEND / ENN / KE at 82M-139M, GRACE at 60M (including the rebuild arm), Pythia-160M collapse under ROME.

So the correct statement is: per-user parametric memory in small chat-like models has been tried, first as persona adaptation (2019) and recently as per-user LoRA with contamination probes (2026, base GPT-2). What is still untested is a chat model at 150M or below that stores facts the user told it, measured by generated recall on held-out phrasings, bleed (other people, unstated slots, open generation, cross-user) and a same-slot correction, against a notes-in-context baseline. The section 4 experiment would still be new, and a clean result either way is still worth publishing.

## Novelty overclaims (ledger ideas marked untested)

1. **L2 rebuild vs stack.** Tried at 60M: GRACE compares sequential fine-tuning (stack) with "FT+Retrain", which periodically fine-tunes the original model on all previous edits (rebuild), on T5-small over 1,000 zsRE edits: rebuild ERR 0.99 vs 0.82, but TRR 0.27 vs 0.56. Near relatives: TemporalWiki (GPT-2 Large 774M) compares training on the diff of changed facts with training on the full snapshot; MemVerse (Qwen2.5-7B) periodically distills a structured long-term memory store into a parametric memory model; arXiv 2607.00368 (Qwen3-1.7B) finds one-step LoRA "conflict correction" 0/24 while text replacement memory resolves 68/72 conflicts. Untested: same-slot corrections (Biscuit to Pickles) for a per-user adapter in a chat model at 150M or below.
2. **L5 meta-train to be writable.** ENN (Sinitsin et al. 2020) is exactly "fine-tune the base so later gradient edits land cleanly", measured at distilGPT-2 82M (ES 0.93) in MEND Table 4. It failed inside BlenderBot-90M on dialogue edits (SERAC Table 3: ES 0.502, drawdown 3.546). PAML is MAML over personas in a tiny chat model; CaMeLS meta-learns token weights for online fine-tuning at DistilGPT2 82M (F1 5.79 vs 3.76); GradMem meta-learns the write at 124M. Untested: meta-learned writability for user facts in a chat model, scored on recall plus bleed. The rationale should cite the BlenderBot-90M failure next to the distilGPT-2 success.
3. **L6 delta-rule state saved per user.** A persisted fast-weight state across sessions exists at 124M (the Hebbian adapter, an outer-product write without the delta correction). LiveMem (arXiv 2608.02515, Qwen3-4B) carries a Gated DeltaNet-2 memory state past context turnover and evaluates on LongMemEval, LoCoMo and FactConsolidation. S0 tuning (arXiv 2604.01168) stores a per-task initial recurrent state for a GatedDeltaNet hybrid (Qwen3.5-4B) as a file, like RWKV state tuning. The ledger's "no test-time-training model has been tested across sessions" is wrong. Untested: a delta-rule layer trained into a chat model at 150M or below, with per-user save and reload and a correction test.
4. **L10 hybrid (notes in context plus adapter).** The general hybrid is known: PRAG's "Combine Both" (in-context plus parametric) at LLaMA-3.2-1B and up, Engram's layered design with RAG, EVAF's "Routed EVAF+RAG" on GPT-2 (goal 0.927, short fact 0.935). Untested: the truncated-notes overflow test at 150M or below.
5. **Report body, section 1.6:** "context-to-weights generators all at 1B or above" and "a tiny generator is untested" are overclaims; MAC tested a T5-small generator for DistilGPT2 82M.
6. **L12 sparse update** is fair as "untested at small scale" for TF-IDF-ranked LoRA rows. It is a transfer from memory-layer slots (1.3B), and memory-layer bases exist at 134M.

## Omissions worth adding

- **arXiv 2607.00368 (July 2026), Qwen3-1.7B/4B/8B:** one-step LoRA updates lower support and answer NLL while generated free-form recall stays at **0/48** on direct, paraphrased and delayed queries. A stronger update (rank 8, 16 steps) reaches 72.9% direct recall but locality falls from 97.9% to 9.7%. Implication for section 4.5: the likelihood-margin tier can move while generation recall stays zero, so pre-register the pass rule on greedy generated recall and report locality next to it. Recall and bleed should be reported as a pair: the stress run shows you can buy one with the other.
- **SERAC ConvSent at BlenderBot-90M** (claim 4 row): the only sub-150M chat-model weight-edit numbers, and they are negative.
- **PAML's in-context arm lost** to weights on consistency at tiny scale (claim 2 row): at 10M-60M the notes-in-context ceiling may be weak enough that weight memory competes, which is a reason to run the Planck checkpoints and not only SmolLM2-135M.
- **Physics 3.1 "fullname" row:** pronoun-subject facts are much less extractable (9.7% vs 48.9% with the name). The note rendering in section 4.2 should include variants with an explicit subject ("the user's dog is called Biscuit") and not only first-person lines.
- **EVAF's actuation finding:** write strength is model-dependent and over-writing raises contamination (Mistral-7B contamination saturated at 1.000 under the strongest setting). The section 4 learning-rate pick should include a contamination check, not only recall.

## Notes for the experiment design (not fact-check verdicts)

- Section 4 plans the runs on this Mac (4-8 h, one process). The brief for this research run says no model may be loaded, trained or benchmarked on this Mac because an earlier multi-agent run caused a kernel panic. Whether a single-process 135M LoRA run is acceptable later is Max's decision; the report's own estimate puts the whole plan under an hour on the RTX 5070, which avoids the question.
- Add a PAML-style arm if cheap: first-order MAML or Reptile meta-training only makes sense for a Planck checkpoint (L5), but PAML's result (plain fine-tuning 0.00, meta-learned 0.20) is the strongest tiny-scale prior that arm A1 will fail, and it should be cited as such.
