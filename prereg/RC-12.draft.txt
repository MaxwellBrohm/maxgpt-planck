2. SCOPE AND BINDING RULES
  Target: conversational mechanics over the conversation's own context. Stored world knowledge is out of scope.
  Knowledge-free families: every gold is stated in the conversation (a user turn, a supplied table, or the model's
    own earlier reply). Only they enter a composite. Knowledge-bearing items (family K) are scored and reported
    separately and never enter a composite or a claim.
  L1 Every item is run through the fake scripted responders of s8 on the REAL items; the gated ones must fail.
  L2 No probe question, answer prefix, or user turn after the gold's statement contains that probe's gold (the
     generator tests go further: no question or prefix contains ANY candidate).
  L3 Every grader fails an empty reply, a loop, a hedge, a negation, a guess list, a reply in the user's voice, a
     wrong in-pool value, a shotgun list, an echo of the question, the stale value and a hypothetical, and passes a
     correct natural sentence. Each clause is mutation-tested (removed, a fixture goes red).
  L4 Knowledge-free and knowledge-bearing scores are never pooled.
  Dev text is Claude-written (a gold set under the D8 provenance rule). Dev and sealed share no template and no slot
  pool. Neither is ever training text: their user turns go into the 13-gram decontamination list (sealed: s13).
  E004 eval items are not reused (E004's fine-tunes saw its training streams); E001/E004 code and ideas are reused.

3. CONVERSATION FORMAT
  Every conversation has exactly 12 scripted user turns u1..u12. User text never depends on the model's replies.
  Own history: the harness sends u1, generates a1, appends a1 as the assistant message, sends u2, and so on to a12.
    Nothing from any gold, IDEAL reply or annotation is ever injected. The reply fed back is the decoded text after
    the stop rule (s4), leading and trailing whitespace stripped; it is stored verbatim with its stop reason (eos,
    eot, role, cap).
  Turn kinds (annotation): S statement of a fact; L same-type lure (a value of the probe's type bound to another
    holder or object); C correction; I standing instruction; O override of an instruction; Q request that makes the
    model commit to an answer (OWN); T passage or table (LOOKUP); D distractor filler; P graded probe; X second
    graded probe in the same conversation. Every D turn also carries asks (true or false), the hand label of its
    filler (F2, s17 OD6 follow-up (2)): false for a plain statement that asks nothing, true for a question or a
    request. It changes only which turns the loop rule counts as asking (s7); for every other purpose the turn is
    kind D.
  Distance: d = index(P) - index(S) in user turns, 1..11; for corrections dc = index(P) - index(latest C of the
    asked object).
  Probe placement: the main probe (for RECALL-abstain and LOOKUP, the LATER of the two probes: D16) is at u12 in 3/4
    of conversations and in the family's early range (usually u9-u11, fillers after) in 1/4, so "the last turn is
    the test" is not learnable from the format.
  Fillers (D): 90 dev fillers (45 how-to/why, 45 small talk/creative), each with a one-sentence IDEAL reply; no
    digit, name-like word, pool value, holder word or PERSIST rule word; 0 word 5-grams shared with E001/E004
    fillers; each used at most once per conversation. Filler replies are graded only by the loop and role-leak rules,
    never for content, so knowledge in a filler answer never moves a knowledge-free score. Each filler carries a
    hand label, read and set one by one (rc12/pools_fill_a.py, pools_fill_b.py): 50 questions (all 45 how-to/why
    fillers and 5 of the small-talk/creative ones), 20 requests (imperatives without a question mark, such as
    "Invent a silly holiday we could celebrate."), 20 statements ("The sunrise was really pretty today."). A D turn
    built from a statement has asks: false (904 of the 4,010 dev D turns; 3,106 have asks: true); the label is data
    copied by the builder and never inferred from the text or its punctuation at grading time (F2, s7, s17 OD6
    follow-up (2)).
  Length: user turns <= 35 words (LOOKUP tables <= 70). Budget: with every reply set to 50 words a conversation stays
    <= 1,800 tokens (proxy 1.35 x words + 4 per turn until a Planck tokenizer exists, then measured). Checked on every
    conversation (G7).
  Truncation (D13): if a rendered history exceeds (model context - 256), the harness drops the oldest WHOLE
    user/assistant pairs and logs it; a probe fails if any S, C, I, O, Q or T turn before it, or any of its source
    turns, was dropped from the history its reply was generated from. (SPEC said the probe's own S/C/I/Q/T turn; the
    rule used is a superset and can only lower a score.) With IDEAL replies the longest dev conversation is 572 proxy
    tokens, so a model with a 2k+ context never triggers it.
  Record (JSONL, one per conversation): id, split, family, cell, seed, turns [{i, kind, text, ideal, facts, vals,
    asks on D turns only}],
    probes [{turn, kind, grader, question, gold or gold_fn, candidates, pool, stale, holder, object_words, pair_id,
    d, dc, src, prefix, ideal, family fields}], meta.unit (mean | all | pair), knowledge flag. The full field list is
    the docstring of rc12/common.py. IDEAL replies are never shown to a model.

4. RENDERS AND DECODING
  Template render (primary for every model that ships a chat template): tokenizer.apply_chat_template(messages,
    add_generation_prompt=True), no system prompt, the model's default system behavior, enable_thinking=False for
    Qwen3-family models. Stop at the template's end-of-turn token(s) or eos; special tokens stripped on decode.
  Plain render (primary for models without a template; reported for every instruct model as a diagnostic, since
    rendering alone moved SmolLM2-135M recall from 0.15 to 0.70 in REPORT s3.2):
      User: <u1>\nAssistant: <a1>\nUser: <u2>\nAssistant:
    Generation starts after "Assistant:"; stop at eos or at the first newline followed by a role tag (User:,
    Assistant:, Human:, any case). Newlines inside a reply are kept and fed back as written.
  Planck: scored in its own shipped template and also in the plain render. Template = the harness ChatTemplate with
    role tokens, encoded with the trainer's own encode call, then <|assistant|>; no system turn, no BOS. Each
    checkpoint is scored with the tokenizer and template it was trained with, recorded by hash (s16). A role token
    in a Planck reply stops generation (stop "role") and is charged as a LEAK. History is fed back as text (the
    stripped decoded reply, re-encoded).
  Decoding (every model, Planck included): temperature 0.6, top-p 1.0, top-k off, repetition penalty 1.0 (off),
    max_new_tokens 256. All are passed explicitly, so a model's generation_config.json cannot change them (Qwen ships
    top_p 0.8, top_k 20, repetition 1.05). 3 sampling seeds per model; per-reply seed = md5(seed, conversation id,
    turn). Greedy is reported as a secondary result.
  Engines: vLLM in WSL2 on the 5070 wherever the architecture is supported; batched HF transformers for Doge,
    MaxGPT-3 and anything vLLM rejects. Conversations advance in lockstep batches (turn t of every conversation in one
    batch). A greedy HF-vs-vLLM parity check on 20 conversations per model family runs before any scored run. The
    locked file names one engine per model (OPEN, s16).
  Rerun check of stored runs (rc12/verify_dev_runs.py --rerun N, rc12/rerun_tie.py; Max, 2026-10-02: took all
    recommendations in rc12/DECISIONS_FOR_MAX.md (item 2)): R1 replays the first N conversations of a sampled run with
    its seed, R2 the same N greedy in lockstep against the same N played one at a time and against the stored greedy
    run. R2 gates and R1 is reported (Max, 2026-10-04: took all recommendations in rc12/DECISIONS_LEVEL_R_FOR_MAX.md
    (decision 3, a); below). For EVERY engine an R2 comparison passes when each conversation's first differing turn
    (where the two prompts are still identical) differs at a near-tie: the margin between the two first differing
    tokens, under one HF forward on that prompt plus their shared prefix, is <= 0.5 nats (the parity rule's NEAR_TIE);
    a turn with no margin (equal
    tokens, a different stop) fails; the identical share is reported. Exact replay is not the bar because the stored
    dev runs drift with the batch on every engine: replayed in batches of 48 instead of 640, turn 1 was identical in
    915 of 2,304 vLLM conversations and 47 of 192 Doge ones (notes STEP 10a). Under sampling one seed's draw can flip
    between two tokens that are not near-tied, so R1 may fail on drift alone. R1 is therefore never a gate: an INFO
    line reports its identical share and, per conversation, the first divergence (id, turn), the shared prefix of the
    two replies (characters) and the margin (rerun_tie.judge, verify_dev_runs; test_verify_dev_runs c_r1_report;
    mutation_verify: R1 gating again, R2 not gating, and the shared prefix, margins or first divergences dropped from
    the report, each killed). verify_dev_runs C3 already checks that the sampling seeds are carried.
    GPU rerun (2026-10-04, rc12/notes.txt STEP 11c; --rerun 5 once per engine family, template render, each in its
    own gpu.lock hold, code md5-equal to this tree): R2 PASSES on both families and R1 FAILS on both, as the line
    above warned. vLLM (Qwen2.5-0.5B-Instruct): R2 lockstep vs sequential and R2 vs the stored greedy run each 1 of 5
    conversations identical, every first divergence within 0.125 nats; R1 0 of 5 identical, margins 0.25, 0.625,
    1.125, 2.125, 2.625. Batched HF (Doge-160M-Instruct): R2 0 of 5 identical both ways, every margin within 0.125;
    R1 0 of 5 identical, margins 0.25, 1.06, 1.12, 2.0, 2.56. C1-C5 pass for both. Both samplers draw a token from
    a seeded noise value (vLLM: argmax of p / q with exponential noise q from the request's generator; batched HF:
    multinomial with the row's generator), so a small drift in p can flip the draw between two tokens whose log
